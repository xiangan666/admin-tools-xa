# Admin Tools 相安版

Minecraft 基岩版 Admin Tools 的二次开发项目，提供管理员统一家园管理、床传送开关、家园访问授权、独立目的地规则及税后物品收益，并完善简体中文。传送始终先满足服务器附加规则，再满足房主规则。自2.5.2起，玩家工具改为3个任意种类原木无序合成，支持混用，并同步全部11种语言的游戏内配方说明；沿用2.5.1的礼包提示清理和中文修复。

## 新增功能

| 功能 | 行为 |
| --- | --- |
| 玩家工具配方 | 3个任意种类原木无序合成1个玩家工具（`jm_at:ticket_menu`），支持不同种类混用；在工作台将3个原木分别放入任意3格。 |
| 独立冷却 | 每个家园、每个传送点分别配置 0–86400 秒整数；0 关闭。按玩家和目的地保存，重进世界仍有效。 |
| 物品费用 | 从配置者当前背包选择物品类型，设置消耗数量；0 不收费。按类型统计多格物品，成功收费，失败退回原物品栈。 |
| 房主物品收益 | 房主设置的费用在成功传送后扣税，净物品进入房主的持久收益账本；房主离线也可收款，上线后查看并领取。 |
| 可配置税率 | 默认 30%，管理员（含服主）可以设置为 0–100% 的整数。不足一个物品的税额按房主和物品类型累计，不因拆分小额传送而免税。 |
| 服务器附加规则 | 先校验服务器规则，再校验该家园的房主规则，两层都通过才可传送；服务器规则不会覆盖房主配置。同类型费用合并核对总量。 |
| 功能开关 | 管理员可关闭全部家园传送规则，或单独关闭冷却、收费、时段；已有房主配置保留，访问授权和单家园传送开关继续有效。 |
| 床传送开关 | 默认开启。管理员关闭后，重新打开的家园菜单隐藏“传送到床”；旧按钮、倒计时和坐骑延后一刻的床传送均会重新检查。 |
| 逐玩家家园管理 | 管理员可管理在线/离线玩家的每个家园：启停家园传送、编辑房主规则、审批申请、授予/修改/撤销访问权限。离线修改持久保存并在上线时按身份同步。 |
| 传送条件确认 | 传送前弹窗显示目的地、当前游戏时间、授权、每层开放时段与冷却、合计物品费用和背包余额；玩家确认后才进入坐骑选择与传送等待。 |
| 等待提醒 | 等待开始立即显示聊天提醒、屏幕倒计时、目的地和“请勿移动”警告；动作栏每5刻刷新，标题每秒更新。覆盖家园、传送点、床、死亡返回和TPA，TPA双方均提醒。 |
| 游戏时间限制 | 使用 24 小时制 `HH:mm`，支持 `22:00 → 06:00`；起始包含、结束不包含；相同时间表示全天。 |
| 家园目录 | 按服主、管理员、协管员、普通玩家分类，显示玩家的家园维度与坐标，支持最近保存的离线家园。 |
| 访问授权 | 房主或管理员可批准、授予授权；所有访客（含管理员）传送仍须持有有效授权，无自动绕过。 |
| 授权条件 | 一次同意、临时权限、永久权限；可限制成功访问次数，0 次上限表示不限。支持主动授权、修改和撤销。 |
| 离线申请 | 申请保存到世界，房主上线收到提醒；7 天未处理自动失效。 |
| 更新保留规则 | 覆盖同名家园或更新其坐标会保留已有规则、家园身份与授权关联。删除再建视为新家园，旧授权失效。 |
| 礼包提示清理 | 菜单领取和脚本事件发放的成功标题在显示结束后主动清空标题与副标题，默认第46游戏刻清理；连续领取、离线与本模组后续传送/挂机/领地标题均有保护。 |
| 中文完善 | 补齐管理日志157种动作、搜索结果菜单位置、时间单位、工单、墓碑、全息图、领地及诊断提示；校正家园、物品栏、合成配方和统计术语。 |
| 语言质量检查 | 中英文各3163个键，检查缺键、重复、占位符、UTF-8编码、格式码及翻译消息误拼为字符串，增加静态中文回归检查。 |

冷却和临时授权使用**现实时间**；开放时段使用**游戏时间**。Minecraft 的 `0` 游戏刻为 `06:00`，`6000` 为 `12:00`，`18000` 为 `00:00`。这两种计时不混用。

## 环境要求

- 基岩版 **26.30 或以上兼容版本**；沿用上游清单 `min_engine_version: [1,26,30]`。
- `@minecraft/server` **2.8.0**、`@minecraft/server-ui` **2.1.0**；不擅自降级上游依赖。
- 行为包和资源包必须同时启用。沿用上游非实验 API 路线；成就可用性需要在实际世界验证，本项目不保证所有平台和未来游戏版本。
- 开发/构建：Node.js 22+、Python 3.11+、npm。CI覆盖Windows与Ubuntu的Node.js 22 / Python 3.12。

## 安装与升级

1. **先备份世界**，特别是升级已有 Admin Tools 世界时。
2. 从上方“版本发布页”下载 `.mcaddon`；需要安装说明、完整文档和授权记录时，下载 `distribution.zip`。可对照 `SHA256SUMS.txt` 校验文件。
3. 双击下载的 `.mcaddon` 导入 Minecraft。开发者从源码构建时，依次执行 `npm ci --ignore-scripts`、`npm run check`、`npm run build`，产物位于 `dist/`。
4. 在世界设置同时启用对应行为包与资源包，将客户端语言设置为简体中文。
5. 通过原版的玩家工具打开“家园”；管理员通过原管理工具管理传送点。

二改版保留上游 BP/RP 的 UUID，并提高包版本，用于在原世界中升级及保留动态属性存档。**不要把原版和二改版同时启用**。新建不同 UUID 的副本会影响上游动态属性归属，不属于本项目的默认升级方式。回退前恢复世界备份，不能依赖低版本读懂新增字段。

升级时，行为包和资源包都应显示上方当前版本，重新进入世界以重载配方、脚本与客户端资源。已有玩家工具可继续使用，新合成使用3个任意种类原木。已有家园、权限、规则、收益及礼包领取记录沿用存档；历史自定义名称和已经保存的旧英文通知不会被批量改写。

**专用服务器升级需要重启服务端进程。** 完成包文件替换与世界绑定更新后，正常停服保存并重新启动，在本次启动日志中确认 `Pack Stack` 实际加载当前版本的 `Admin Tools 相安版 行为包`，再让客户端重连。运行中的服务器会继续使用启动时加载的配方；磁盘文件已更新或客户端重新连接，不能单独证明新配方已加载。完整步骤见 [专用服务器升级与排查](docs/SERVER_UPGRADE.md)。

上游原始下载包和解压内容保存在本地 `upstream/`，已加入 Git 忽略；来源、文件编号、SHA-256 见 [UPSTREAM.json](UPSTREAM.json)。

## 使用入口

- **自己的家园规则**：玩家工具 → 家园 → 家园传送规则 → 选择家园。
- **传送点规则**：管理工具 → 传送点管理 → 传送规则（冷却 / 物品 / 时段）。沿用原传送点管理权限。
- **查看他人位置 / 申请访问**：玩家工具 → 家园 → 玩家家园目录（按角色）→ 角色 → 玩家 → 家园。
- **处理申请 / 主动授权**：玩家工具 → 家园 → 家园访问申请与授权。
- **使用已获授权**：重新从家园目录选择目的地并发起传送；同意申请不会强制移动申请者。
- **查看与领取收益**：玩家工具 → 家园 → 家园收益。
- **管理员统一入口**：管理工具 → 家园统一管理（管理员）；管理员也可从“玩家工具 → 家园”进入。
- **服务器规则、床传送与税率**：统一管理 → 服务器家园规则、床传送与税务。
- **逐玩家设置**：统一管理 → 逐玩家管理家园权限与规则 → 玩家 → 家园。

房主本人不需要访问授权，但仍受管理员设置的单家园传送开关约束，并须通过启用的服务器与房主两层规则。服务器附加费用独立消耗，不计入房主收益；税率只作用于房主规则的费用。管理员代改房主规则不会把收益转给管理员。公共传送点继续沿用原独立规则，不纳入家园收益或家园策略。床传送单独受床传送开关控制；普通坐标传送、TPA、死亡返回等原功能不绑定某个家园的规则。

家园或传送点传送前会先显示条件确认窗。确认后才进行坐骑选择和全局延时；取消不扣费。若等待期间权限、规则或目的地变化，系统会重新校验并取消过期确认。

等待时请保持原地不动。屏幕和动作栏会显示剩余秒数及移动取消警告，开始时聊天也会提醒；到达、取消或离线会清理等待提示。全局延时为0时直接执行，不显示等待倒计时。此延时与传送成功后的目的地冷却不同。
