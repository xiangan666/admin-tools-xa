# 使用说明

适用版本：[README当前版本](../README.md)。维护作者：**相安**（3199912548@qq.com）。

## 合成玩家工具

在工作台中，将 **3个任意种类原木** 分别放入任意3个格子，即可无序合成 **1个玩家工具**（`jm_at:ticket_menu`）。可以使用同一种原木，也可以混用，例如橡木原木、白桦原木、云杉原木各1个。材料按原版 `minecraft:logs` 标签匹配，木板不能代替原木。

2.5.2起不再使用旧的纸和红石配方。管理员与玩家信息页的合成配方说明已同步更新，升级前已获得的玩家工具可继续使用。

## 专用服务器更新配方

专用服务器需要更新服务器上的行为包与资源包、当前世界的两份包绑定文件，然后正常停服保存并重新启动。启动后，在**本次启动**的日志中确认 `Pack Stack` 显示当前版本行为包，再让玩家重连测试合成。服务器运行期间覆盖包文件不会自动刷新已加载的配方，客户端重连也不会重载服务端配方。完整检查步骤见 [专用服务器升级与排查](SERVER_UPGRADE.md)。

## 升级与礼包提示

备份世界后导入 当前版本的 `.mcaddon`，确认世界启用的行为包和资源包都为当前版本，然后重新进入世界以重载配方与资源。沿用原世界存档即可，礼包领取记录、家园规则、授权和物品收益继续保留。

从“玩家工具 → 礼包”领取成功，或通过原有NPC/命令方块脚本事件收到礼包后，成功标题和礼包名会短暂显示，再主动清空。默认淡入5刻、停留30刻、淡出10刻，第46游戏刻清理，正常20刻/秒时约2.3秒；服务器卡顿时现实时间会相应延长。连续领取以最新一次计时；如果随后出现本模组的传送、挂机或领地标题，旧礼包清理任务会停止，不会抹掉这些新提示。

自2.5.1起补齐中文菜单路径、管理日志动作、时间单位和多处实时状态提示，并检查乱码、语言键和占位符。已有玩家自定义礼包名称、身份组、欢迎词、全息图内容，以及存档中的旧英文通知保留原文；新生成的系统通知使用新版文案。完整范围见 [本地化说明](LOCALIZATION.md)。

## 配置一个家园

先在玩家工具中保存家园。进入“家园 → 家园传送规则”，选择家园后配置：

1. 冷却填写 `0` 至 `86400` 的整数秒数。
2. 收费物品下拉框列出**配置时背包中实际存在**的类型，并显示数量。当前背包没有的旧收费类型可保留现有配置。
3. 数量为 `0` 不收费；大于 `0` 时必须选择有效物品类型。收费按物品 ID 匹配，不要求访客物品的自定义名称、附魔与示例完全相同；不要用稀有自定义物品作为通用货币。
4. 开启时间限制后填写 `HH:mm`。示例 `08:00–20:00` 为白天开放；`22:00–06:00` 跨午夜开放；`00:00–00:00` 全天。
5. 保存。修改家园坐标或覆盖同名家园不需要重新设置规则。

房主规则按每个目的地分别存储，不会修改其他家园或公共传送点。管理员可以另设全局家园规则：传送先满足服务器规则，再满足该家园的房主规则，任一层不满足都会拒绝。房主配置不会被服务器附加规则替换。管理员关闭的规则项在房主页面不能修改，但原值会保留，重新启用后继续使用。传送等待时间沿用上游的全局传送延时，与成功后的冷却是两个设置。

## 家园收益与领取

房主设置收费后，访客成功传送支付的这笔房主费用会按当前税率结算。默认税率为 **30%**，其余物品进入房主的持久收益账本。房主离线不影响收款；在“家园 → 家园收益”查看累计赚取、税额、净收入、已领取和待领取物品，再选择领取。

物品按整数结算，小数税额会累计。例如初始无余数，收取 10 个绿宝石时缴税 3 个、房主收益 7 个。若每次只收 1 个绿宝石，30% 税额的余数按同一房主和物品类型累计；第 4 次会产生第 1 个整物品税，累计 10 次仍总计缴税 3 个、净收入 7 个，不会因拆分支付长期免税。

领取仅能操作自己的账本。背包满时未发放部分保留在账本，不掉落到地面；请留出空间后继续领取。传送失败或取消不会给房主新增收益，也不消耗税额余数。收费按物品类型匹配，但收益需要能安全保存与还原实际物品数据；如果所扣物品含无法安全重建的特殊数据，本次传送会拒绝并退款，而不是把它悄悄变成普通同类物品。详细支持范围与故障边界见 [家园收益说明](HOME_REVENUE.md)。

## 服务器规则与税务

管理员（包括服主）通过“管理工具 → 家园统一管理（管理员）→ 服务器家园规则、床传送与税务”进入；也可从管理员自己的家园菜单进入统一管理。协管员和普通玩家无权更改这些全局设置。管理员可以：

1. 设置家园全局附加冷却、消耗物品与允许游戏时段。
2. 设置房主费用税率，整数 `0–100%`；`0%` 全部归房主，`100%` 全部为税，不产生可领取净物品。
3. 关闭全部家园传送规则，或分别关闭冷却、收费、时段功能。相应开关关闭时，两层的该项校验都跳过；不会清空已有房主配置，也不会绕过房主同意与访问次数授权。
4. 设置“允许传送到床”。默认开启；关闭后重新打开家园菜单时不显示该按钮，之前已打开的按钮或正在等待的床传送也无法继续执行。该开关独立于规则总开关，不会改变床重生机制。

双层规则的效果：服务器冷却 60 秒、房主冷却 120 秒时，必须两层都结束；服务器允许 `08:00–20:00`、房主允许 `10:00–16:00` 时，只能在两段交集内传送。服务器费用 2 个绿宝石、房主费用 10 个绿宝石时，背包至少需有 12 个；其中 2 个为服务器附加消耗，10 个按税率结算房主收益。不同类型费用分别核对，任一项不足都不收费。

## 管理每一位玩家的家园

进入“家园统一管理（管理员）→ 逐玩家管理家园权限与规则 → 玩家”。选择某个家园后可启停传送、编辑该家园的房主规则，或管理该家园的申请与授权；玩家页也可统一查看其全部家园授权。支持离线玩家。

关闭单家园传送后，房主本人和已有授权访客都不能使用此家园传送；原规则、授权和收益保留。该开关不受“关闭全部家园规则”影响。管理员可在规则功能暂停时预先编辑房主规则，保存本身不会启用已关闭的功能。玩家原有的自管规则入口仍保留。

离线修改保存到世界，目录和传送立即读取修改后的值，玩家下次上线时合并回真实家园记录。若该家园已删除并重建，旧修改不会应用到新家园。更多见 [管理员统一管理](ADMIN_HOMES.md)。

服务器附加费用与税项独立消耗，不进入房主可领取余额；本版没有服主税款领取功能。此策略只作用于家园，不改变公共传送点规则。

## 配置公共传送点

持有传送点管理权限的管理人员，在管理工具的“传送点管理”中创建目的地，然后打开“传送规则（冷却 / 物品 / 时段）”。各项字段与家园相同。原公共、工作人员、仅管理员三档可见性继续生效。

## 访问别人的家园

在家园目录中先选角色，再选玩家和家园。目录展示维度及坐标；**展示位置不等于授予传送权限**。

- 没有权限时可提交“一次同意”“临时权限”或“永久权限”的申请。
- 临时权限填写有效分钟数；现实时间计时，从主人批准时开始，包括玩家离线期间。
- 设置次数限制，`0` 表示不限；一次同意固定为一次。
- 房主可以同意申请条件、更改条件后授权，或拒绝。
- 房主离线也可以提交申请；上线后有待处理提醒，7 天后未处理申请自动过期。
- 获批后重新选择家园发起传送；不会强制传送申请者。

主人也可在“访问申请与授权 → 主动授权玩家”中直接给予已加入世界的玩家权限，并在已有授权列表修改或撤销。管理员可通过统一管理代为审批、授权或撤销。授权只绑定一名玩家和一个家园；管理员没有自动传送特权，需要访问时也应先取得房主或管理员明确授予的有效授权。

## 传送结果

选择家园或传送点后，会先显示条件确认窗，包括目的地位置、当前 Minecraft 游戏时间、访问授权是否有效、每层规则的时段和冷却状态、总费用及背包现有数量。检查信息后选择“确认传送”才继续坐骑选择与全局延时；选择取消不会扣费。条件窗打开后若规则、权限或目的地发生变化，后续校验会取消这次请求，需要重新发起并确认。

确认后和真正执行传送前都会重新检查目的地、权限、时间、冷却和背包。家园/传送点等待时移动超过约半格或切换维度会取消；同一玩家同时只允许一项此类规则传送。

有等待延时时，开始立即显示三种提醒：聊天说明目的地与等待秒数；屏幕中央显示倒计时，副标题提醒“请勿移动，移动会取消传送”；动作栏持续显示剩余秒数、目的地和移动警告，每5刻刷新一次，标题每秒更新。家园、传送点、床、死亡返回及TPA均接入提示，TPA接收方会看到“等待玩家”且双方都要保持不动。移动取消会显示取消原因；成功、取消或离线后停止刷新并清理等待提示。全局延时为0时没有倒计时。

- 取消、余额不足、时间不符、权限失效、目的地删除或实际传送失败：不开始冷却，不扣访问次数。
- 费用在实际移动前扣除；移动失败立即退回原物品栈，保留其名称、附魔等元数据。
- 原槽位异常被其他扩展占用时，退款尝试回包；剩余物品会掉落在玩家脚下并提示，请拾取。
- 成功：扣除启用的两层费用、记录该玩家到该目的地的冷却、扣一次有限访问次数；房主费用扣税后的物品入房主收益账本。

删除家园后重建同名家园属于新家园，原授权不会复活。单纯更新/覆盖坐标保留规则和家园身份。离线家园来自最近保存镜像，尚未加入新版世界的旧玩家可能需要先上线一次才有镜像。

## 排错

| 现象 | 排查 |
| --- | --- |
| 按钮显示翻译键或 `%1$s` | 确认BP/RP均为当前版本并已下载新版资源包，客户端语言为简体中文；重新进入世界。记录完整键名和出现的页面。 |
| 出现 `[object Object]` 或乱码 | 本版增加翻译消息拼接和编码检查；先核对实际启用的版本与资源缓存，再记录原文字样、页面、触发步骤及内容日志，联系维护者。 |
| 领取礼包后标题一直停留 | 确认行为包已升级并重新进入世界；正常应在第46游戏刻主动清理。若仍残留，记录是否加载了其他HUD/资源包、游戏版本和内容日志，便于核对客户端显示竞争。 |
| 历史通知或自定义名称仍是英文 | 升级不批量重写历史通知及用户内容；可在对应编辑页面修改自定义内容，新生成的系统提示使用新版文案。 |
| 无法打开新表单 | 检查游戏支持清单声明的 Script API；关闭聊天或其他表单后重试。 |
| 时间看似不对 | 使用游戏时钟，不是电脑时间；`/time set` 会改变时段判断。 |
| 冷却仍在继续 | 现实秒计时；更改游戏时间不会清除冷却。 |
| 传送时没有倒计时 | 确认BP/RP均为当前版本，并检查全局传送延时是否大于0；等待提示只在实际进入等待后显示。动作栏可能与其他模组竞争，请同时查看中央标题和聊天提醒。 |
| 玩家工具仍显示旧配方或无法合成 | 本地世界确认启用当前版本行为包与资源包后退出并重新进入世界；专用服务器完成更新后必须正常停服并重新启动，在本次启动日志确认实际加载当前版本。将3个原木分开放入工作台任意3格，可混用树种。原木须匹配 `minecraft:logs`，木板不适用。 |
| 授权保存失败 | 存储写入失败或容量不足时不会默默授予；请查看内容日志，不要反复重置数据。 |
| 房主配置未生效 | 检查管理员设置的总规则开关及该项功能开关；服务器附加规则与房主规则必须同时满足。 |
| 看不到传送到床 | 管理员已关闭床传送；请由管理员在家园统一管理的服务器设置中启用。 |
| 家园已有授权仍不可传送 | 检查该家园的管理员传送开关，关闭后房主和授权访客均受限。 |
| 收益未全部领出 | 检查背包空间；未发放余额保留在账本，可稍后继续领取。 |
| 收益出现待核对记录 | 不要反复领取或重置账本；保留世界备份及内容日志，联系维护者核对存储故障/异常退出前后的实际传送。 |
| 升级丢失数据 | 检查是否使用相同 BP UUID、是否加载原世界备份；不要同时激活两个版本。 |
