# 专用服务器升级与配方排查

适用版本见 [README当前版本](../README.md)。维护者姓名：相安；邮箱：3199912548@qq.com。

基岩版专用服务器在加载世界时读取行为包配方。运行期间替换包文件后，当前进程仍可能继续使用启动时的旧配方。服务端正常停服并重新启动，才会加载更新后的包；客户端重连不能代替服务端重启。

## 升级步骤

1. 确认服务器实际运行目录和 `server.properties` 中的 `level-name`，据此定位 `worlds/<level-name>/`。通过管理器启动时，注意路径可能是指向真实目录的链接。
2. 正常停服，等待进程退出，备份当前世界和已有Admin Tools两包。
3. 安装同一当前版本的行为包与资源包。保留行为包UUID `e700a3a7-14b3-44d3-8b57-fd05498fc778`、资源包UUID `5d31bcd8-8682-42e2-8860-ce75e7a3c742`，不要并行启用原版与二改版。
4. 在当前世界 `world_behavior_packs.json` 与 `world_resource_packs.json` 中，将对应条目的版本更新为两包 `manifest.json` 的 `header.version`，保留其他包、顺序和资源子包选项。
5. 通过原管理器或启动方式重启，等待 `Server started.`。
6. 在**此次启动**的日志中确认 `Pack Stack` 包含当前版本的 `Admin Tools 相安版 行为包`，并检查相关加载错误。
7. 客户端重连并获取新版资源包。在工作台任意3格分别放入3个原木，另测混合树种、原木不足、木板和旧纸加红石配方；预期仅3原木配方可以合成玩家工具。

本项目构建和GitHub发布不会自动替换服务器文件或重启进程。只向本机Minecraft客户端导入安装包，也不会更新独立专用服务器。

## 判断新配方是否加载

| 检查位置 | 应看到的内容 | 证据范围 |
| --- | --- | --- |
| 服务器两包 `manifest.json` | 同一当前包版本 | 磁盘安装状态。 |
| 服务器 `recipes/ticket_menu_recipe.json` | 无序合成，3个 `minecraft:logs` 材料槽，结果1个 `jm_at:ticket_menu` | 磁盘配方内容；木板不适用。 |
| 当前世界两份包绑定文件 | 与安装清单版本和UUID一致 | 世界配置状态。 |
| 本次启动 `Pack Stack` 日志 | 实际加载更新后的行为包 | 运行状态，仍需实际合成验收。 |

## 回退

正常停服后，同时恢复升级前世界及BP/RP备份，再恢复相应世界包绑定。保留原UUID并不保证低版本能理解新增数据；仅替换低版本安装包不等于恢复存档。
