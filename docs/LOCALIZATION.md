## 两种显示方式

支持RawMessage的原生表单、聊天、标题等界面使用资源包语言键与 `t()` / `raw()`；嵌套的物品名称和时间消息按客户端语言渲染。不要把这些对象放进普通模板字符串、用 `+` 拼接，或用 `String()` / `JSON.stringify()` 当成显示内容，否则可能显示 `[object Object]` 或原始结构。

DDUI `ObservableString`、实体nameTag、计分板显示名和持久化通知只接收普通字符串，使用服务器端简体中文。不同语言客户端看到这些共享文字时仍为中文。英文与其他上游语言框架保留；本次完整键与占位符配对检查以en_US/zh_CN为准，未声称补齐其他语言的新增翻译。

## 保留的数据与技术内容

玩家/礼包/家园/身份组等自定义名称、管理员编辑的欢迎词和全息图、工单与通知中的玩家原文保留。已有存档中的旧英文通知、旧计分板名称或自定义身份组不会被批量重写；新生成的系统文字使用新版文案。日志的动作标签即时翻译，历史详情字符串则保留写入时内容。

品牌、实际命令、命名空间、物品/属性/事件ID、权限key、角色枚举、搜索词和开发诊断中的技术字段保留原值。例如 `jm_at:claimkit`、`minecraft:emerald`、`KIT_EVENT_CLAIM` 是有效标识；日志页面把动作代码显示为中文，并仍用原代码过滤。物品名称优先使用物品自身的语言键，缺少语言键的第三方物品可能回退到名称或ID。

时间显示和输入分开：玩家看到“1小时 30分钟”，礼包编辑字段使用 `1h 30m` 等原有输入语法。`parseDuration` / `fmtDurationExact` 保留 `d/h/m/s`，防止中文显示文案改变数据解析或丢失秒数。

## 编码和翻译格式

源码、JSON和 `.lang` 均使用UTF-8。语言资源的 `\n` 是游戏内换行，`%1$s` 等位置参数必须与英文键一致。Minecraft `§` 格式码保留，正文解释中出现的字面量 `§` 不应被随意替换。不要用“另存为ANSI”或不匹配的系统代码页重写文件。

`npm run validate` 自动执行：

1. 发货文本严格UTF-8解码，拒绝非法字节；检测替换字符、常见UTF-8错解码痕迹和异常控制字符。
2. 语言键重复、空值、格式码和占位符检查，en_US/zh_CN键与占位符配对。
3. 脚本中的静态语言键存在性、`t()`参数数量和直接将RawMessage转为字符串的检查。
4. 已修复静态英文的只读回归检查；`check-static-chinese.mjs` 不支持 `--write`。

`npm test` 使用合成损坏样本检查工具是否报错，并加载实际代码验证日志过滤、搜索显示、时间渲染和礼包设置。静态检查不能识别所有动态拼接路径或评价全部翻译语义，因此实际页面巡检仍有必要。早期迁移记录见 [localization-audit.md](localization-audit.md)，其中的旧行号和替换清单属于历史资料。

## 礼包标题清理

菜单领取和NPC/命令方块脚本事件使用同一限时反馈助手，默认第46游戏刻清空标题与副标题，正常20刻/秒时约2.3秒。连续领取更新任务；本模组后续传送/挂机/领地标题使旧任务失效；离线释放任务。默认时间根据游戏刻计算，服务器卡顿会延长现实等待。

原实现只设置淡入/停留/淡出，没有主动清空。当前修复增加明确的结束写入；截图所用客户端HUD的位置、其他附加包是否再次写入同一标题，仍需在原问题环境验收，不能仅凭截图确定全部原因。

若升级后仍有残留、英文句子、乱码、翻译键或占位符，请记录实际BP/RP版本、客户端语言、页面与操作、完整异常文字、其他HUD/资源包组合和脱敏内容日志，发送至维护邮箱。
