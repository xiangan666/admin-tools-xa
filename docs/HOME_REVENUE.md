# 家园双层规则、税务与物品收益

维护作者：**相安** · 联系邮箱：**3199912548@qq.com**。

## 两层规则的关系

家园保留各自的房主规则，管理员统一设置一层服务器全局家园规则。服主也属于管理员。执行顺序为：

1. 检查该家园的传送开关、有效访问授权、目的地及其他基础条件。
2. 检查服务器启用的附加冷却、开放时段和物品费用。
3. 检查该家园房主启用的冷却、开放时段和物品费用。
4. 核对两层费用的合计库存与收益账本可结算性；都满足后才执行实际传送。

**两层是 AND 关系：先满足服务器规则，再满足房主规则。服务器规则不覆盖或替换房主配置。** 任一层拒绝，都不能只按另一层放行。

| 设置示例 | 结果 |
| --- | --- |
| 服务器冷却60秒，房主冷却120秒 | 两层都必须结束后才能再次传送。 |
| 服务器允许08:00–20:00，房主允许10:00–16:00 | 必须在两层允许区间交集内，即10:00–16:00。 |
| 服务器允许22:00–06:00，房主允许00:00–04:00 | 跨午夜正确求两层条件，只有00:00–04:00都允许。 |
| 服务器收费2个绿宝石，房主收费10个绿宝石 | 至少需要12个，不能拿同一批10个分别通过两次检查。 |
| 服务器收费1个钻石，房主收费10个绿宝石 | 两种费用都要足额，任一种不足均不扣费。 |

家园冷却按玩家和目的地保存成功时间，两层用各自秒数检查该成功时间。时间仍为 Minecraft 游戏时钟，税和收益记录不使用游戏时刻推算现实冷却。

## 管理员可控制的设置

进入“家园统一管理（管理员）→ 服务器家园规则、床传送与税务”。2.5.0起管理员（含服主）均可修改，协管员和普通玩家不能修改；提交表单时再次验证管理员身份。

- **家园规则总开关**：关闭后跳过两层家园传送规则，保留原配置。
- **冷却、收费、时段独立开关**：关闭某项后，两层的该项都不执行；房主页面不能修改被关闭的项，已保存值保留。
- **传送到床**：默认开启，关闭后隐藏床传送入口并阻止尚未完成的床传送。独立于规则开关。
- **附加冷却**：0–86400整数秒；0表示服务器这一层不加冷却，房主启用的冷却仍生效。
- **附加费用**：从操作管理员当前背包选择物品类型，数量0表示这一层不收费，房主费用仍按其设置执行。
- **附加时段**：使用24小时制 `HH:mm`，支持跨午夜；关闭服务器这一层时段限制不会取消房主启用的时段限制。
- **房主费用税率**：默认30%，可设置0–100%的整数。

总开关和单项开关不关闭房主同意、授权有效期、访问次数或家园目录；没有授权仍不能访问别人的家园。公共传送点不适用此家园策略，继续使用各自原规则。

管理员还可从统一管理按玩家/家园编辑房主规则和访问授权、启停指定家园的传送。单家园传送关闭不受规则总开关影响，也不删除历史收益；管理员代改房主规则时，净收入仍归该家园所有者。详见 [ADMIN_HOMES.md](ADMIN_HOMES.md)。

## 谁收到哪些物品

传送支付分为独立的两笔：

| 来源 | 去向 |
| --- | --- |
| 服务器附加费用 | 独立消耗，不进入房主账本。 |
| 房主费用中的税额 | 独立扣除，不进入房主可领取余额。 |
| 房主费用扣税后的净物品 | 进入该家园房主的收益账本，房主可查看和领取。 |

本版提供房主净物品领取，没有服主税款领取功能。修改税率只影响后续成功结算，不会重算已入账收益。仅未来成功传送产生收益，升级前2.3.1已经消耗的费用不会追溯补发。

房主离线可以收款。房主自己的家园传送仍执行启用的两层规则，不因为自己是收款人而免除费用和税额。删除家园不会把已经赚取的物品随家园一起删除；收益按房主保存，目的地信息用于记录来源。

## 整数税额与余数

物品数量是整数，不能对一次1个物品的支付直接发放0.7个物品。实现按**同一房主 + 同一物品类型**累计百分之一物品的税额余数，而不是每次独立舍去小数：

```text
总税额分子 = 本次房主费用数量 × 当前整数税率 + 上次税额余数
本次整数税 = floor(总税额分子 / 100)
本次新余数 = 总税额分子 % 100
本次房主净收入 = 本次房主费用数量 - 本次整数税
```

例如税率30%，初始余数为0：

| 成功支付 | 本次费用 | 本次税 | 房主本次净收入 | 税余数 |
| --- | ---: | ---: | ---: | ---: |
| 第1次 | 1 | 0 | 1 | 30 |
| 第2次 | 1 | 0 | 1 | 60 |
| 第3次 | 1 | 0 | 1 | 90 |
| 第4次 | 1 | 1 | 0 | 20 |
| 累计10次 | 10 | 3 | 7 | 0 |

一次收10个同类物品也是税3、净收入7。不同家园但同一房主、同一收费类型共用该类型的余数，不能换一个家园名称继续舍去小数。0%不新增税额；100%不产生可领取净物品。失败或取消不会推进余数。

## 查看和领取

在“家园 → 家园收益”查看待领取物品、累计毛收入、累计税额、累计净收入和已领取情况。页面只读取当前真实玩家自己的账本，不能通过传入别人的ID领取他人的收入。

- 选择某类物品或领取可领取物品。
- 按实际物品最大堆叠数分栈放入背包，不假定所有物品都能堆64个。
- 背包不足时，只发放能放入的部分，剩余继续留在账本；不把收益掉落在地。
- 领取成功不会增加毛收入或净收入，只减少待领取余额、增加已领取数量。
- 重复点击不会把同一余额重复发放；存储或物品写入异常会明确提示，应检查日志后再处理。

收益账本有容量保护，不能无限累计互不兼容的物品数据；接近容量时应及时领取。容量不足的结算会拒绝本次传送并退款，不静默丢掉房主收入。

## 收费物品的数据安全

原费用按物品类型匹配；退款保留实际扣除的原物品栈。收益长期保存时，还需要能安全序列化并重建物品数据，不能只存一个类型ID后把特殊物品变成普通物品。

普通钻石、绿宝石、铁锭等货币适合收费。常见且可以验证往返一致的可堆叠自定义数据可随收益保存；如果物品含API无法完整保存和重建的特殊载荷，则明确拒绝该次结算并退款。不要把装有物品的潜影盒、地图、成书等复杂数据物品作为通用收费货币。实际允许范围以程序的安全校验和错误提示为准，不宣称支持所有原生或第三方物品数据。

## 失败、存储异常与崩溃边界

费用在实际移动前托管，并准备**不可领取的收益预留**。只有真实玩家传送成功才提交房主收益和税额余数。取消、物品不足、授权失效、时段/冷却不满足、目的地变更或实际移动失败时，会取消预留、退回费用，不产生房主收益。

Minecraft 没有跨玩家背包、坐标和世界动态属性的原子数据库事务。正常失败路径有回滚和防重保护，但异常断电或进程被强制终止可能留下待核对记录。程序不会在重启时把不确定的预留自动变成可领取收益；请保留世界备份与内容日志核对。若实际移动已成功而随后存档失败，不能把已成功移动改判为失败并退费，否则会形成免费传送或复制物品。

同样，领取过程中存档/背包API故障会采用保守保护，避免重复发放；故障未排除前不要手动重置余额或反复强制领取。本说明不承诺所有存储损坏、崩溃或其他模组篡改背包时都能自动恢复。

游戏内多人、跨平台、存档重启和背包满领取仍须按 [验收清单](TESTING.md) 实测；本地自动测试不代替游戏实测。
